Architecture decision needed: send return connects to finalOutputMixer (bypasses master insert chain — typical DAW) or to preMasterMixer (wet signal passes through master inserts). This diagram shows the finalOutputMixer option. See existing-state.md §3 for tradeoffs.

Key rules

  • Each track fans out: dry → preMaster AND parallel send tap(s)
  • Send amount (0–100%) is per-track, per-bus — independent
  • Send A and Send B are always present; no user creation needed
  • Send return reaches output automatically — no user routing
  • Pre/post-fader toggle deferred (stretch goal)

Interactions

  • Click a send-tap node to adjust level (inline slider)
  • Click a send bus node to open insert chain (prototype 02)

Prototype notes

  • This diagram answers Story 3's core question: where does the send return enter the master output? The open architecture decision (return to finalOutputMixer vs preMasterMixer) is surfaced as an annotation bubble.
  • The "↓ & →" notation on track arrows is shorthand for the fan-out: the signal splits to both the dry path and the send tap simultaneously. Is this legible? An alternative is to show the fan-out as a T-junction graphic.
  • Muted track is greyed out throughout the flow — confirming that mute does not send to the send buses (or does it? This is an open question).
  • Send bus nodes are clickable stubs that reference Prototype 02 for the insert chain editor — keeping this diagram focused on topology.
  • Open question: does this "flow view" belong in the app as a real screen, or is it only a planning artifact? The per-track send knobs in prototype 01 may be sufficient and this overview only useful during design review.
  • Adversarial fixture: a muted track with full sends — should a muted track still route signal to send buses?

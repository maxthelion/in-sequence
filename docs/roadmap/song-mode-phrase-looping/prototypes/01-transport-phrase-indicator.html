Queued phrase row: name in amber, "Queued ✓" replaces "Queue" button. Selecting a different phrase cancels the prior queue. "Now" remains available on the queued row — pressing it switches immediately and clears the queue.

Open questions surfaced by this wireframe
  1. Dropdown dismiss on "Now": Does pressing the immediate-switch button dismiss the dropdown automatically, or does it stay open so the performer can see the updated state? The wireframe above dismisses it (simpler) — confirm with user.
  2. Cancel queue: Should tapping the "Queued ✓" button on the already-queued phrase cancel the queue (return to no-queue state)? The wireframe does not implement cancel; re-queueing a different phrase is the only cancel path.
  3. Dropdown backdrop: Does tapping outside the dropdown dismiss it? The prototype uses a simple outside-click listener; real implementation should confirm gesture conflicts with the Tracks UI below.
  4. Cycle-progress granularity: The cycle-progress bar animates in real time. Is per-bar granularity sufficient, or should it be per-step? Affects perceived latency of the "at end of cycle" label.
  5. Queue button label width: Long phrase names (e.g. "Phrase D (Outro / Bridge Reprise)") overflow the queue button when shown inline. Should the button truncate with ellipsis, or show only a count/icon when a phrase is queued?

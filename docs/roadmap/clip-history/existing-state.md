# Existing State

## Summary

The underlying capture model is already much closer than expected. The engine keeps a rolling per-track note history, can convert that history into a note-grid clip, and can save the result into a pattern slot. The missing work is mainly UX: there is no generator-view entry point, no history modal, no way to audition a chosen historical window as a virtual clip, and no save-to-slot flow exposed to the user.

## Existing Support

- `Sources/Engine/EngineController.swift:12` defines a private rolling capture step and buffer.
- `Sources/Engine/EngineController.swift:21` defaults that buffer to 64 steps.
- `Sources/Engine/EngineController.swift:39` converts recent capture steps into `ClipContent.noteGrid`.
- `Sources/Engine/EngineController.swift:607` exposes `capturedClipContent(trackID:lengthSteps:)`.
- `Sources/Engine/EngineController.swift:617` exposes `saveRollingCapture(to:trackID:destinationSlotIndex:lengthSteps:name:)`.
- `Sources/Document/Project+CapturedClips.swift:4` chooses a preferred capture destination slot, avoiding the currently selected slot where possible.
- `Sources/Document/Project+CapturedClips.swift:10` creates a captured clip pool entry and assigns it to a pattern slot.
- `Sources/UI/TrackSource/TrackSourceEditorView.swift:154` shows the current pattern slot palette at the top of the source editor.
- `Sources/UI/TrackSource/TrackSourceEditorView.swift:240` has a generator-source panel and `GeneratorParamsEditorView`, which is the natural place for a Clip History entry point.
- `Sources/UI/TrackSource/Preview/GeneratedNotesPreview.swift:3` shows a generated-note preview, but it is a deterministic preview from current generator settings, not the rolling performance history.
- `Tests/SequencerAITests/Engine/EngineControllerTests.swift:502` verifies that rolling capture can write a new note-grid clip to a chosen destination slot.

## Divergence From Target UX

- No visible Clip History button exists on the generator view.
- No modal exists for browsing generated notes going back 16 bars.
- No UI exposes the rolling capture buffer as a timeline or note view.
- No current UI switches playback to a virtual clip of the historical output.
- No history-window selection or clip-length control exists.
- No save-to-pattern-slot chooser exists for captured history, even though the underlying save API accepts a destination slot.
- Occupied pattern slots are visible in the existing palette, but there is no capture-specific overwrite, duplicate, or conflict flow.

## Model And Semantics Gaps

- The current rolling buffer keeps 64 steps by default. If the intended 16 bars means 16 bars of 16th-note steps, the buffer needs 256 steps, not 64.
- Capture appears to store resolved notes after the source and modifier chain have been evaluated. That likely matches "generated by the chain", but the spec should say whether modifier output is included.
- The save API creates a real clip immediately. There is no separate model for temporary "virtual clip" audition.
- The current code can create clips of a requested step length, but there is no product decision yet for allowable lengths, default length, or how the selected historical window maps into shorter or longer clips.
- The current behavior for empty history is implicit: no `ClipContent` is returned. The UX needs an explicit empty state.

## Test Coverage

Existing coverage verifies the basic model path: generate one step, save it to slot 1, and confirm the resulting clip has the expected pitch, velocity, length, and note-grid shape.

Missing coverage includes:

- rolling window size for 16-bar history;
- saving multi-step and sparse generated history;
- clipping or padding behavior when requested length differs from available history;
- post-modifier versus pre-modifier capture semantics;
- UI flow for opening history, changing length, auditioning, and saving to a slot;
- occupied-slot overwrite or conflict behavior.

## Prototype Implications

The first prototypes should focus on the generator-source panel and modal flow:

- one button in the generator view opens Clip History;
- the modal shows recent generated output as a 4x4 frozen history source matrix;
- the selected one-bar virtual clip is visually distinct and drives the modal's audition state;
- a length control changes the captured clip window;
- pattern slots are shown at the bottom as save targets, with occupied slots unmistakably marked;
- empty, partial-history, and occupied-slot states should be reachable with fixture data.

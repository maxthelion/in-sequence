# Clip History Notes

## Raw Intent

The user wants a way to capture useful generated track output after hearing it, or to make a generator-driven track more predictable.

## Clarified Concern

A track may have a generator chain running live. The user can hear generated material they like, but the current workflow does not provide an obvious way to inspect recent generated output and save it as a concrete clip/pattern.

Clip history should bridge from generative exploration to predictable authored material.

## Desired Flow

1. A generator is running for a track.
2. The generator view has a button that opens a Clip History modal.
3. The modal shows notes generated by the chain, going back 16 bars.
4. Playback switches to a virtual clip made from historical output over a single bar.
5. The virtual clip length is modifiable.
6. Pattern slots for the track are shown at the bottom as "save to pattern slot" targets.
7. Saving to a slot creates a new clip in that pattern slot from the selected historical output.

## UX Intent

- Let the user capture a good generated moment without needing to manually recreate it.
- Let the user audition historical output as a predictable virtual clip before committing it.
- Keep the save destination concrete: choose a pattern slot and create a real clip there.
- Keep generator exploration and clip authoring connected rather than separate modes.

## Open Design Questions

- Should the 16-bar history be fixed or configurable?
- Does the one-bar virtual clip default to the most recent bar, the selected bar, or the currently playing bar?
- How does the user select which historical bar or region becomes the virtual clip?
- Can the saved clip overwrite an existing pattern slot, or only fill empty slots?
- Should capture include generator-chain note output only, or also post-modifier output?
- What happens when the generator emits non-note events or parameter automation?

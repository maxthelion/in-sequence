Story 3 — Scope selection.
Existing-state resolved to phrase-level per-track as the first-pass scope.
Rationale: stepInPhrase is the single integer all per-track note resolution reads. A phrase-level map replaces it once and every track in the phrase uses the remapped index. Track-level would require a per-track remap call inside the per-track loop in prepareTick.
This screen shows the scope selector UI and what each scope means operationally.
Step Order — Scope Selector
Apply this map to:
Phrase scope: The step-order map is applied to all tracks inside the selected phrase simultaneously. One map covers the whole phrase. stepInPhrase → stepOrderMap[stepInPhrase] before any per-track resolution.
Phrase / Track scope: Each track in the phrase has its own independent toggle and map. The remap is applied inside the per-track loop in resolvedStepNotes(…stepIndex:…) before calling resolvedStep(phraseID:trackID:stepInPhrase:). More flexible but requires a second lookup per track per tick.
Affected tracks — "Main groove"

Architecture note — why not project-scope first?
Project-scope (one shared map) is the simplest data model but cannot be per-phrase without extra indirection. Phrase-level is the sweet spot: one map per phrase, stored in PhrasePlaybackBuffer alongside patternSlotIndex. Project-scope is deferred to a future iteration.
